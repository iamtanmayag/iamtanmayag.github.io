03 / CLOUD & DATA 2025

Moving production data without losing its identity.

Application and data migration from AWS Mumbai to N. Virginia, with client IDs and billing consistency preserved.

MY ROLEApplication changes and data migration
SELECTED TOOLSAWS S3 · PostgreSQL · AWS RDS · Python · SQL
03 / 06

Real engineering work, shared at a level that respects company and client confidentiality.

Discuss the work
THE CHALLENGE

Why this mattered

US-based clients requested a US data region. Moving application data was complicated by region-dependent configurations and identifier mismatches that could break client-specific logic or billing.

THE ENGINEERING

What I did

01

Decouple the region

Replaced hardcoded dependencies with environment-aware application configuration.

02

Protect the data model

Migrated client PostgreSQL and S3 data while accounting for conflicting IDs and billing-related records.

03

Verify each flow

Executed SQL checks and manually validated individual client workflows and services across the cutover.

THE OUTCOME

What changed

The transition was completed without customer-visible downtime in production observations.

Ownership, precisely.

I owned internal code changes and data migration. An external infrastructure provider handled the underlying cloud architecture relocation.
